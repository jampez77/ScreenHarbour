# ScreenHarbour 0.2.49 — prerelease

Full-screen seasonal rows now finish positioning on initial focus, without needing another Left/Right press. Native CSS smooth scrolling could compete with expansion and leave the scene short of its final position. Seasonal focus now temporarily suppresses that scrolling, restores the original declaration and settles below the header. Late font or header changes also receive a final alignment.

Expansion commits the final layout once and animates the visible layers with compositor transforms. This avoids continuously changing row padding and repainting the large background throughout the animation. Parallax, animated doors, themed headings and reduced-motion support remain available.

Remote navigation measures adjacent candidates instead of all 60 posters on every horizontal move. Vertical movement checks only the controls needed to preserve the selected column and uses final row positions while expansion is still moving. Arrow, focus and scroll events share saved-position work; activation and Back still save immediately. Temporary smooth-scroll overrides no longer cause Home to rediscover and reattach its rows.

In a Chromium comparison with 6× CPU throttling, a 60-poster Nightmare scene with parallax, frames, doors and full-screen expansion used approximately **60% less main-thread work and 79% less paint work** over three expansion/collapse cycles. Twelve horizontal moves used about **7% less main-thread work**. These are two-run browser averages against 0.2.48, not a measured frame-rate improvement on the physical LG television.

All saved settings, row positions, seasonal dates, frames, doors, ranks, shuffle choices, local fonts and smaller lazy-loaded TV images are preserved. No configuration changes are needed.
